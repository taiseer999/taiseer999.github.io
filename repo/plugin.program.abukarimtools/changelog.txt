v3.0.1
- Fenlight: kill volume auto-drop. Fenlight's volume_checker() in resources/lib/modules/kodi_utils.py
  is the same as RedLight's - it runs on every playback start and clamps the player to
  fenlight.playback.volumecheck_percent (default '50'), which on Kodi's 0..-60 dB scale lands
  on -30 dB, so every title starts at half volume with no settings-screen opt-out. Body replaced
  with an immediate return (exact-blob match against Fenlight 2.5.3, with a def volume_checker()..
  except:pass fallback regex). New toggle 'Fenlight: Kill Volume Auto-Drop'; joins the automatic
  boot/update sweeps and is re-applied after a Fenlight update like every other patch.

v2.9.8
- AUTO-PATCH: the service now self-restarts Kodi once after an in-place update of ABUKARIM TOOLS itself. Kodi registers the new add-on folder mid-session but does not launch the freshly-registered service until a restart, so the auto-patch watchdog stayed dormant until the next manual reboot - meaning updates to Seren/TinyPPI/AF3/DexWorld/TMDbHelper/RedLight were not re-patched in the meantime. A version stamp in addon_data triggers a single reboot on the first boot after the tools update; one-shot and loop-safe, and the first-ever run (fresh install/build) is skipped since the build flow already reboots.
- SPEED TEST: new Maintenance item "Speed Test" that runs an Ookla speedtest.net bandwidth test (download / upload) and shows the shareable result image, with a matching Kodi Speed Test icon. Ported from ez Maintenance+ and made Python 3.14 clean.

v2.9.5
- REBUILD ADD-ON DATABASE: phase 1 now deletes Addons33.db from autostart.sh instead of from inside Kodi. Kodi holds the database open for the whole session and rewrites it during shutdown, so an in-process delete did not reliably survive the reboot - which is why the rebuild appeared to do nothing. autostart.sh runs before Kodi, so the delete always sticks.
- The injected block is guarded by a trigger file (/storage/.addons33_rebuild_pending) and deletes only that trigger, never itself: rewriting a running shell script mid-read is unsafe on BusyBox ash. A block left behind for any reason is therefore inert on every later boot. Phase 2 removes the block text from Python, from a separate process, and leaves any other content in autostart.sh (including the backup/restore block) untouched.
- REBUILD: phase 2 now runs Fix Add-on Update Origins automatically once the add-ons are back. A freshly built Addons33.db has empty origin fields, so add-ons would not resolve to their repository for updates; origin_fix repairs them just before the final restart.
- REBUILD: on non-CoreELEC platforms (macOS dev box) the tool no longer quits silently. Kodi cannot relaunch itself there, so it now deletes the database, tells you Kodi is about to close, and finishes the rebuild automatically the next time you open Kodi.

v1.7.3.3
- FIRST-RUN "sometimes does not auto start" FIX (3 root causes):
  1) Crash-resilient trigger: the self-trigger now keys off first_run.done (written only on COMPLETION, storing the build id) instead of last_build.id (written at ARM time). Previously a kernel panic / power-cycle mid-sequence (flag already consumed, done never written) left the trigger permanently satisfied and first-run silently never ran again. An interrupted run now simply re-arms on the next boot. Legacy 'done' markers are migrated in place, so devices that already completed first-run do NOT re-run it.
  2) Service-killing UnicodeDecodeError: _cleanup_stale_autostart read autostart.sh as strict UTF-8 catching only OSError; corrupted bytes (a possible leftover of the pre-1.7.3 sed self-edit bug) raised UnicodeDecodeError, killed service.py before the first-run trigger was ever evaluated. Now reads with errors='replace', and the boot chores are individually fenced so nothing can block the trigger.
  3) Reboot race: the CoreELEC reboot prompt moved out of _run_steps to AFTER the done marker is written — a user-approved Reboot could previously race the finally block and (with the new done-keyed trigger) would have re-run the whole sequence next boot.
